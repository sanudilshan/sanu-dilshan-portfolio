# Responsive audit — current portfolio

At the 1440px desktop viewport, the hero presents a confident art direction but gives too much horizontal authority to the permanent rail and to the unoccupied grid area. The heading is very large while its supporting summary, proof ledger, and action row cluster too tightly in the lower-right, reducing scan clarity. The rail should become a narrower brand/navigation anchor and the hero should use a more deliberate two-column desktop grid.

At the 390px mobile viewport, the hero’s bottom proof ledger competes directly with the primary CTA and the heading. Its labels appear visually compressed, so the hero does not create a clean reading path from headline to explanation to action. The revised mobile layout should move the proof items into a separate horizontal summary band after the hero, reserve adequate bottom space for the CTA, and increase the mobile header’s usable tap area.

Typography should move away from the current purely systems-led grotesque/mono relationship. The next version will use **Bricolage Grotesque** for display headlines and project titles, **Manrope** for readable body copy, and retain **IBM Plex Mono** only for concise metadata. This gives the portfolio a modern, slightly playful editorial voice while protecting recruiter readability.

## Verification result

The revised desktop hero now uses a slimmer rail and a clear split layout: evidence has a dedicated left-side structure while the headline, explanation, and actions have a stable right-side reading column. The content no longer competes for the same lower-right space.

At the 390px mobile viewport, the hero follows a clean order—identity, message, explanatory copy, action, then proof ledger—with the engineering rows separated from the primary CTA. The full-page mobile and desktop checks show the project cards, experience entries, stack sections, and contact block wrapping without visible overflow or collapsed hierarchy.
